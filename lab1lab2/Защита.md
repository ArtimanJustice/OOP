# Защита — Лабы 1–2 (консольное приложение «Shadow Maiden»)

Хронометраж: 5–7 минут. Сначала приложение (~1.5 мин), потом код (~4–5 мин). Идти быстро, по верхам.

## Часть 1. Демонстрация (0:00 – 1:30)

Запусти проект (F5 в Rider/VS или `dotnet run`).

Говори:
- «Это консольная игра-рогалик. Персонаж ♀ ходит по подземелью, управление — WASD или стрелки. Цель: найти ключ, открыть дверь и дойти до выхода ✦. Всего три уровня.»
- Походи по полю. Подбери предмет — внизу меняются статы: «HP — здоровье, ATK — атака, Keys — ключи».
- Подойди к врагу (☠ скелет / ▼ мышь / ◆ босс) — «при столкновении идёт бой: я бью врага, он бьёт меня, HP падает».
- Возьми ключ, открой дверь ▬, зайди на выход → «переход на следующий уровень, статы сохраняются».
- Покажи экран Game Over или Victory, рестарт на R.

## Часть 2. Код (1:30 – 6:30)

Открывай файлы по порядку, на каждом — одна-две фразы.

**1. `Program.cs`**
«Точка входа — top-level statements. Создаём движок и запускаем: `new GameEngine().Run()`.»

**2. `Models/ElementType.cs`**
«Перечисление всех типов объектов поля — стена, пол, игрок, враги, предметы.»

**3. `Models/GameElement.cs`**
«Абстрактный базовый класс всех объектов. Хранит координаты X, Y и тип. Абстрактное свойство `IsPassable` — можно ли пройти сквозь клетку. Это абстракция: базовый класс задаёт контракт, наследники реализуют по-своему. Использован primary constructor C# 12.»

**4. Наследники GameElement — `Wall`, `Floor`, `Door`, `Exit`, `Player`**
«Наследование и полиморфизм: каждый переопределяет `IsPassable`. Стена — false, пол и выход — true, а у двери `IsPassable => IsOpen`, то есть зависит от состояния. В `Player` — Hp, Attack, Keys и методы TakeDamage / Heal; поля закрыты, наружу — свойства (инкапсуляция).»

**5. `Models/Enemy.cs` + `Skeleton`, `Bat`, `Boss`**
«Второй абстрактный класс — враг. Hp с `private set` — инкапсуляция. `virtual GetMove` — ИИ по умолчанию идёт к игроку. Скелет и босс используют это поведение, а `Bat` переопределяет `GetMove` (летает случайно) и `CanFly`. Это полиморфизм: один вызов `GetMove` — разное поведение.»

**6. `Models/Item.cs` + `Sword`, `Potion`, `Key`**
«Абстрактный предмет с абстрактным методом `Apply(player)`. Меч повышает атаку, зелье лечит, ключ добавляет ключ — каждый класс реализует Apply по-своему.»

**7. `Models/GameField.cs`**
«Игровое поле: двумерный массив клеток плюс списки врагов и предметов. Главное — индексатор `this[x, y]` с проверкой границ: доступ к массиву инкапсулирован, выход за пределы возвращает null вместо исключения.»

**8. `Services/LevelLoader.cs`**
«Загрузка уровня из текстового файла: читаем строки и по символу создаём нужный объект через switch. Сами карты — в папке `Levels` (level1–3.txt), их можно открыть и показать.»

**9. `Services/ConsoleRenderer.cs`**
«Отрисовка в консоль: проходим по полю, для каждой клетки через pattern matching выбираем символ и цвет. Внизу — панель HP/ATK/Keys/Level, HP меняет цвет по остатку здоровья.»

**10. `Engine/GameEngine.cs`** (главный файл)
«Здесь вся игровая логика. `Run()` — игровой цикл: отрисовать, прочитать клавишу, обработать. `MovePlayer` — движение, бой, открытие двери, переход на выход. `MoveEnemies` — ход врагов: спрашиваем у каждого `GetMove` и двигаем, если можно.»

## Вывод (1–2 фразы)
«Проект построен на ООП: три абстрактных класса — GameElement, Enemy, Item; наследование и полиморфизм для разных объектов; инкапсуляция через свойства и индексатор. Логика игры отделена от отрисовки и загрузки уровней.»
